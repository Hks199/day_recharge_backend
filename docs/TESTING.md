# Verification

Run `npm ci`, `npm run typecheck`, `npm run lint`, `npm run build`, `npm test`. Vitest/Supertest integration tests create a new isolated MongoDB replica set with transactions and real indexes; never connect to development/production data. Test signing secrets are random per process. Test-only credentials exist only within the ephemeral test database.

The first run downloads MongoDB 8.2.6 (large on Windows); setup timeout is 10 minutes. Subsequent runs use mongodb-memory-server's cached binary. Network access, available disk space and compatible MongoDB platform binaries are needed. Set MONGOMS_SYSTEM_BINARY to an existing compatible mongod executable to avoid downloads. Hooks cleanly stop the replica set after tests.

Coverage includes tenant provisioning, DNS challenge verification, unverified/unknown domains, shared API Origin mapping, proxy spoofing, the creation matrix, direct and Distributor-managed Retailers, cross-tenant IDs/tokens/body manipulation, downline access, suspension/expiry/renewal, funding approval, duplicate transfers, concurrent overdrafts, insufficient balances, fractional money, ledger immutability, compensating reversals, mock success/failure/timeout, callback signature and replay, direct commission payouts, refunds/reversal idempotency, bill inquiry/payment, scoped reports, refresh rotation/reuse and CSRF, NoSQL credential rejection, support/notifications and health/OpenAPI.

Service-level tests exercise the same processor called by BullMQ, without requiring Redis. With Compose MongoDB/Redis running, execute `npm run test:smoke`. Set SMOKE_MONGODB_URI if using a non-default mapped MongoDB port, for example `mongodb://127.0.0.1:27018/?replicaSet=rs0&directConnection=true`. This checks real HTTP readiness/login/provisioning/funding and outbox -> Redis/BullMQ -> a separate worker -> SUCCESS, plus exact wallet/ledger values. It creates and removes only a random smoke database and queue prefix. See IMPLEMENTATION_STATUS for actual results and external verification limits; these tests do not prove third-party provider connectivity.
