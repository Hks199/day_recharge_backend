# Security model

Tenant IDs are server-resolved and validated against active user/session scope. Every tenant query includes tenantId or uses a trusted financial job's globally unique transaction after retrieving its tenant. There is no tenant impersonation endpoint. Platform scope is explicit, role-restricted and audited. Verified domain selectors provide routing, not authorization. Unknown domains and disallowed Origins fail closed.

Passwords: Argon2id, 64 MiB memory, time cost 3, one lane. Password change/reset revokes all sessions. Refresh credentials and CSRF values are hashed in MongoDB. JWT verifies HS256, issuer/audience and short expiry, then checks the session and user on every request. Refresh rotation detects reuse and revokes token families. Only refresh/logout use cookie credentials and both require CSRF headers. HttpOnly/Secure cookies use SameSite=None for HTTPS, Lax for deliberate localhost HTTP development. Access APIs do not accept cookies as access authentication.

Strict Zod schemas reject unknown privileged fields and NoSQL operator objects. Query filters are assembled from primitives and validated IDs, never directly from JSON. Requests are limited to 32 KiB (256 KiB for the owner-only website content editor), Helmet sets headers, CORS is dynamically verified per tenant, login/reset are rate limited and general traffic has a bounded rate. Default rate-limit storage is per-process; production multi-instance rate enforcement should additionally run at the shared gateway. IP trust must reflect real proxy topology.

Pino redacts authorization/cookies/request bodies/password hashes/tokens/secrets. Audit records contain actor/action/resource IDs rather than credentials. Public configuration returns explicit safe fields. Production errors omit exception text and stack. Provider signatures use constant-time comparisons, short timestamp windows and durable replay IDs. Mock webhook secret is distinct from JWT signing secret.

Money is integer-only, atomically updated with an append-only ledger, guarded by idempotency and conservative state transitions. Confirmed refunds settle even if tenant or wallet is blocked. Real-time external calls never occur inside a database transaction. Developer and Super Admin funding/reversal privileges are sensitive and require actual banking/provider evidence, operational separation and audit review.

Before production, configure TLS at edge and database, private authenticated Redis, least-privilege service users, encryption at rest, backup restore testing, key rotation, centralized alerts and shared rate limits. Add MFA/step-up auth for platform and high-value financial approval if required by your operational risk policy; this implementation does not provide MFA. Production security review and provider/regulatory verification remain deployment gates.
